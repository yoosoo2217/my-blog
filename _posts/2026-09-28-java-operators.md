`a > b`나 `age++` 같은 식은 어떻게 값을 만들어낼까? [이전 글]({{ site.baseurl }}/java-type-casting.html)의 형변환에 이어, 값을 계산하고 조건을 만들 때 쓰는 연산자를 종류 암기보다 쓰임 중심으로 정리한다.

> **TL;DR**
> - 비교 연산자의 결과는 항상 `boolean`이다.
> - `&&`는 왼쪽이 `false`면 오른쪽을 실행하지 않는다(단락 평가). 조건 순서는 실행 여부에도 영향을 준다.
> - `++age`는 증가 후 값을, `age++`는 증가 전 값을 식의 결과로 쓴다.

## 1. 산술 연산자와 문자열 +

```text
+  더하기
-  빼기
*  곱하기
/  나누기
%  나머지
```

`%`는 "모드"가 아니라 **나머지 연산자**다.

```java
int result = 10 % 3;
System.out.println(result);
```

```text
1
```

문자열과 함께 쓰는 `+`도 있다.

```java
int age = 20;
System.out.println("age = " + age);
```

```text
age = 20
```

문자열과 숫자를 `+`로 연결하면, 숫자가 문자열로 변환되어 그대로 이어 붙는다.

## 2. 비교 연산자: 결과는 boolean

```text
==  같다
!=  다르다
<   작다
>   크다
<=  작거나 같다
>=  크거나 같다
```

핵심은 비교 연산의 **결과가 boolean**이라는 것이다.

```java
int a = 5;
int b = 3;
boolean isGreater = a > b;
System.out.println(isGreater);
```

```text
true
```

`a > b`라는 식 자체가 `true`나 `false` 값을 만들어내기 때문에, `boolean` 변수에 그대로 저장할 수 있다.

## 3. 논리 연산자와 진리표

```text
&&  그리고(AND)
||  또는(OR)
!   부정(NOT)
```

| A | B | A && B | A \|\| B |
|---|---|---|---|
| T | T | T | T |
| T | F | F | T |
| F | T | F | T |
| F | F | F | F |

`!`는 참/거짓을 반대로 뒤집는다. `!true`는 `false`가 된다.

## 4. 여러 조건을 함께 검사하기

회원가입에서 "아이디 중복 검사"와 "비밀번호 길이 검사"를 **모두** 통과해야 가입이 되는 경우, 두 조건을 `&&`로 묶어서 검사한다.

```java
boolean isIdAvailable = checkIdDuplicate(id);      // 아이디 중복 검사
boolean isPasswordValid = checkPasswordLength(pw); // 비밀번호 길이 검사

if (isIdAvailable && isPasswordValid) {
    System.out.println("가입 가능");
}
```

## 5. `&&`는 왼쪽부터 확인한다 (단락 평가)

수업에서 "아이디 중복 검사(시간이 걸리는 무거운 검사)"와 "비밀번호 8자 이상 검사(가벼운 검사)"를 `&&`로 묶었을 때, **어느 조건을 왼쪽에 두는 게 유리한지**를 다뤘다.

`&&`는 왼쪽 조건을 먼저 평가하고, 그 결과가 이미 `false`라면 오른쪽 조건은 평가하지 않는다. 이를 **단락 평가**(short-circuit evaluation)라고 한다.

```text
A && B
```

A가 `false`면 전체 결과는 이미 `false`로 확정되므로, B는 실행되지 않는다.

수업에서는 이 예시로 속도보다 더 중요한 걸 짚었다.

- 오른쪽 조건은 왼쪽 결과에 따라 **아예 실행되지 않을 수도 있다.**
- 그래서 오른쪽 조건 안에 값을 바꾸는 등 부작용이 있는 코드가 있다면, 그 코드가 실행되지 않아서 예상과 다른 결과가 생길 수 있다.
- 즉 조건을 어떤 순서로 쓰느냐는 논리적인 결과뿐 아니라, **그 조건이 실제로 실행되는지 여부**에도 영향을 준다.

무거운 검사(아이디 중복 검사)를 오른쪽에 두면 그 검사를 아예 안 하고 끝나는 경우가 생기는 것도 이 성질 때문이다. 다만 이를 "무거운 검사는 오른쪽에 둔다"는 성능 팁으로만 받아들이지 말고, 위 세 가지를 기억해두는 게 더 중요하다고 배웠다.

## 6. 증감 연산자: 전위 vs 후위

```text
++  1 증가
--  1 감소
```

전위(`++age`)와 후위(`age++`)는 "언제 값을 증가시키느냐"가 다르다.

```java
int age = 20;

System.out.println("초기 값 age : " + age);
System.out.println("age : " + (++age));
System.out.println("age : " + age);
System.out.println("age : " + (age++));
System.out.println("age : " + age);
```

```text
초기 값 age : 20
age : 21
age : 21
age : 21
age : 22
```

- `++age`(전위): **먼저 1을 증가**시키고, 증가된 값을 식의 결과로 사용한다.
- `age++`(후위): **현재 값을 먼저** 식의 결과로 사용하고, **그 다음에** 1을 증가시킨다.

네 번째 줄(`age++`)이 21을 출력하는 이유가 여기 있다 — 이 줄이 끝난 뒤 실제로 `age`는 22가 되지만, 출력에 쓰인 값은 증가하기 전 값이다.

## 정리

- 산술 연산자에서 `%`는 나머지를 구하고, 비교 연산자의 결과는 항상 `boolean`이라는 걸 정리했다.
- `&&`가 왼쪽부터 평가되고 조건에 따라 오른쪽을 아예 실행하지 않을 수 있다는 단락 평가 개념이 가장 새로웠다 — 조건의 순서가 단순한 스타일 문제가 아니라는 걸 알았다.
- 전위·후위 증감 연산자는 "언제 증가시키는지"의 차이라는 걸 코드 결과로 직접 확인하고 나서야 확실히 구분됐다.
- 다음에 볼 것 : 삼항 연산자와 조건문(`if` / `switch`)이다.

## 더 학습하면 좋은 개념

- **삼항 연산자(Ternary Operator)** — `조건 ? 값1 : 값2` 형태로, 오늘 배운 비교·논리 연산자의 결과를 바로 값 선택에 쓸 수 있는 연산자다. `if`문을 짧게 쓸 때 유용해서 다음에 익혀보고 싶다.
- **비트 연산자** — `&`, `|`, `^`, `<<`, `>>`처럼 논리 연산자와 비슷해 보이지만 비트 단위로 동작하는 연산자들이다. 오늘 배운 `&&`, `||`와 헷갈리지 않게 구분해서 알아두면 좋을 것 같다.
- **조건문(if / switch)** — 오늘 만든 `boolean` 값들은 결국 조건문의 조건식으로 쓰인다. 연산자 다음 단계로 자연스럽게 이어지는 주제다.
