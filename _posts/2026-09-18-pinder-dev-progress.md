같은 서비스를 여러 AI 도구로 나눠 만들다 보면, 지금까지 무엇이 만들어졌는지 한눈에 보이지 않는다. **p:nder(pinder)** 프로젝트에서 9월 15일부터 17일까지 진행한 작업을, 작업에 쓴 도구별 기록(Claude Code, gpt-1, gpt-2, Claude Design)에서 모아 영역별로 다시 정리했다.

> **TL;DR**
> - 9/15에 Next.js로 화면을 이식했고, 9/16에 인증과 데이터를 실제 백엔드로 바꿨다. 9/16~17에는 AI 도우미, 카카오맵 경로, AI 일정 생성을 붙였다.
> - 9/17에는 모바일 반응형 작업이 집중됐고, 모바일 Planner 하단 버튼 배치는 네 도구의 기록에 모두 나올 만큼 반복해서 고쳤다.
> - 알림 클릭 이동, 커뮤니티 사진 필수화처럼 두 도구의 기록에 함께 나오는 기능은 같은 작업인지 확인이 필요하다.

Claude Code의 기록은 날짜가 함께 남아 있어서 큰 흐름을 이것으로 잡았다. 다른 도구의 기록에는 날짜가 없다.

| 날짜 | 한 일 |

| 9/15 | Next.js 프로젝트 초기화, 디자인 프로토타입을 Next.js로 리뉴얼, 주요 화면 이식, 로그인·회원가입 세션 연결, Google 로그인 연동 |
| 9/16 초 | 인증·경로 데이터를 목업에서 실제 백엔드/DB로 교체, 마이페이지·커뮤니티·탐색 데이터 전환, 이메일 인증, 비밀번호 찾기, 회원탈퇴·재가입 정리 |

## 2. Claude Code: 기능 구현과 백엔드 연결

화면 이식부터 백엔드 전환, AI 기능까지 가장 넓은 범위를 맡았다.

**초기 세팅과 화면 이식 (9/15)**
- 홈, 탐색·마이페이지, 내 일정, 커뮤니티, Route Planner, 로그인·회원가입 화면을 기존(legacy) 디자인 그대로 옮겼다. 헤더와 푸터는 공용 컴포넌트로 합쳤다.
- 로그인·회원가입을 실제 세션으로 연결하고 Google 로그인을 붙였다.

**백엔드·인증 전환 (9/16 초)**
- 마이페이지의 프로필·알림 설정과 커뮤니티·탐색의 게시글·여행지 데이터를 실제 백엔드로 바꿨다.
- 이메일 인증은 Resend에서 Gmail SMTP로 전환했다. 비밀번호 찾기, 회원탈퇴·재가입 흐름, 프로필 사진 업로드, 가입 전 이메일 중복 확인, 구글 첫 로그인 시 회원가입 화면 경유도 정리했다.

**AI 도우미와 Route Planner (9/16~17)**
- Gemini 기반 AI 도우미 채팅을 추가했다. 무료 티어 한도 문제 때문에 모델을 여러 차례 바꿨고, 타이핑 표시, 자동 스크롤, 마크다운 기호 제거 같은 사용성도 다듬었다.
- "변수 추가"에 자유 텍스트를 넣으면 AI가 동선을 다시 짜는 기능을 만들고, AI 추천 장소는 검색 확인 팝업 흐름으로 합쳤다.
- 카카오맵 연동으로 경로선을 실제로 그리고, 이동수단별 경로 조회의 동시성 문제를 고쳤다. 지도 핀은 일차별 색상으로 통일했다.
- 여러 날짜를 한 번에 보는 모드에서는 일차별 출발지 일괄 선택, 일차별 최적경로 캐시, 일차 간 경로 분리를 넣었다.
- 현재 위치 버튼, 방문지 클릭 시 지도 이동, 일정 날짜 변경 모달, 계산된 경로 함께 저장도 추가했다.
- 초대 링크는 보기 전용과 편집 가능으로 나누고, 편집 링크는 승인제로 정리했다.

**내 일정, 커뮤니티, 탐색, 알림**
- "AI 생성하기" 마법사(지역, 스타일, 관심사, 동행, 이동수단)로 여행 일수만큼 날짜별 동선을 자동 생성한다. 내 일정 카드에는 제작자(왕관)와 참여자를 표시한다.
- 커뮤니티는 비로그인 진입 차단 안내, 댓글·답글 삭제, 사진과 댓글 2단 구조의 상세 화면, 사진 필수화와 4:3 크롭, 최신순 정렬을 넣었다.
- 탐색은 "이 여행지로 일정 짜기"를 실제 AI 동선 생성과 연결하고, 날짜 선택을 당일치기·1박2일·2박3일 선택으로 바꿨다.
- 알림벨은 기존 디자인대로 재현해 실제 백엔드와 연결하고, 편집 권한 요청을 알림에서 바로 승인·거절할 수 있게 했다. 알림 클릭 시 관련 화면으로 이동하는 기능은 9/17에 이미 구현되어 있었다(커밋 `8508237`).

**모바일과 인프라**
- 모바일 헤더, 지역 토글, Planner 슬라이드 레이아웃을 다시 만들었다. 지도 복귀 버튼 위치를 검색창과 겹치지 않게 여러 차례 조정했고, AI 도우미 버튼 위치와 iOS 자동 확대 방지도 처리했다.
- 다크모드 가독성을 전반적으로 점검하고, 환경변수 누락으로 생긴 빌드 실패를 고쳤다.

## 7. 헷갈리기 쉬운 점: 겹치는 기록은 같은 작업일까

알림 클릭 이동은 Claude Code 기록에 "9/17에 이미 구현됨"으로, gpt-1 기록에도 구현 항목으로 나온다. 커뮤니티의 사진 필수화와 최신순 정렬도 두 기록에 모두 있다. 같은 작업을 두 도구가 각자 기록한 것인지, 서로 따로 구현한 것인지는 이 기록만으로 알 수 없어서 `확인 필요`다. 커밋 기록을 같이 대조해 봐야 구분된다.

모바일 Planner 하단 버튼은 네 도구의 기록에 모두 나온다. 한 화면의 버튼 배치를 여러 번에 걸쳐 여러 도구가 고쳤다는 뜻이다. 레이아웃 기준을 먼저 정하고 시작했다면 줄었을 반복인지는, 이 기록만으로는 단정할 수 없다.

## 8. 정리

- 3일 동안 목업이던 화면을 실제 백엔드, 카카오맵, Gemini 기반 AI 기능이 붙은 서비스로 바꿨다.
- 9/17에는 모바일 반응형에 작업이 몰렸고, Planner 하단 버튼 배치는 모든 도구에서 반복해서 조정했다.
- 겹치는 기록(알림 이동, 사진 필수화)은 커밋 기록으로 같은 작업인지 확인해야 한다.

다음에 볼 것은 아래 "더 학습하면 좋은 개념"에 적었다.

## 더 학습하면 좋은 개념

- **반응형 웹과 뷰포트(Viewport)** — 모바일 레이아웃을 이번에 여러 번 다시 고쳤다. 미디어 쿼리와 뷰포트 개념을 알면 "기준을 먼저 정하고 고치는" 순서를 잡을 수 있다.
- **OAuth 2.0과 세션 관리** — Google 로그인과 세션 연결을 붙였다. 인증 흐름이 어떻게 이어지는지 알면 첫 로그인 때 회원가입 화면을 거치게 하는 식의 예외 처리를 설계하기 쉽다.
- **API 호출 제한(Rate Limit)과 캐싱** — Gemini 무료 티어 한도 때문에 모델을 여러 번 바꿨고, 경로 조회는 캐시로 줄였다. 한도와 캐시 전략을 같이 보면 외부 API 의존 기능을 더 안정적으로 만들 수 있다.
- **역할 기반 접근 제어(RBAC)** — Creator, Editor, Viewer, S-viewer 권한을 나눴다. 권한을 표로 정리하는 방식을 알면 공유 링크 같은 기능의 허용 범위를 일관되게 정할 수 있다.
- **Web Storage(`localStorage`)** — Product Tour를 최초 1회만 보여주는 데 썼다. 저장 용량과 브라우저별 차이를 알면 "한 번만 보여주기" 같은 상태를 어디에 둘지 판단할 수 있다.
