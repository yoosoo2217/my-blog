조건이 서로 다른 두 조회 결과를 한 번에 받고 싶을 때 `UNION`을 쓴다.  
수업에서 작성한 쿼리는 그대로 실행하면 실패하는 코드였기 때문에, 실패하는 이유와 고친 방법을 함께 정리했다.

> **TL;DR**
> - `UNION`은 여러 `select`의 결과를 하나로 합치는 수학의 합집합이고, 중복된 행은 제거한다.
> - 합치려면 `select`마다 컬럼 개수가 같아야 하고, 컬럼 순서와 데이터 타입도 호환되어야 한다.
> - 수업 코드는 첫 `select`가 2컬럼, 둘째 `select`가 3컬럼이라 실패한다. 둘 다 `name`, `email`, `status` 3컬럼으로 맞추면 된다.

환경: MySQL (버전 `확인 필요`). 실습 테이블은 `users`이고, 쿼리 결과는 이 글에 옮기지 않았다.

## 1. 문제 상황: 상태가 다른 사용자를 한 번에 조회하고 싶다

`users` 테이블에는 사용자의 상태를 나타내는 `status` 컬럼이 있고, 이 실습에서 다루는 값은 `active`, `suspended`, `deleted` 세 가지다.  
요구사항은 다음과 같다.

- `active` 사용자와 `suspended` 사용자 모두에게 이메일을 발송한다.
- 탈퇴한 `deleted` 사용자는 제외한다.
- 사용자의 이름, 이메일, 상태를 조회한다.

`status = 'active'`인 행과 `status = 'suspended'`인 행을 각각 조회한 뒤 결과를 이어 붙이면 된다. 이때 쓰는 것이 `UNION`이다.

## 2. UNION은 무엇을 하는가

`UNION`은 각각의 쿼리문의 결과를 합친다. 수학의 합집합과 같아서, 두 결과에 똑같은 행이 있으면 한 번만 남기고 제거한다.

흐름을 순서대로 적으면 다음과 같다.

1. 첫 번째 `select`가 `active` 사용자를 조회한다.
2. 두 번째 `select`가 `suspended` 사용자를 조회한다.
3. `union`이 두 결과를 합치고, 중복된 행은 제거한다.

합칠 때 지켜야 하는 규칙은 두 가지다.

| 규칙 | 내용 | 어기면 |
|------|------|--------|
| 컬럼 개수 | 모든 `select`가 조회하는 컬럼 개수가 같아야 한다 | 합칠 수 없다 (아래 에러 케이스) |
| 컬럼 순서와 데이터 타입 | 같은 위치의 컬럼끼리 데이터 타입이 호환되어야 한다 | 엉뚱한 컬럼끼리 합쳐진다 |

컬럼 순서가 중요한 이유는 `UNION`이 컬럼 이름이 아니라 **위치**를 기준으로 결과를 이어 붙이기 때문이다. 첫 번째 `select`의 두 번째 컬럼과 두 번째 `select`의 두 번째 컬럼이 같은 열이 된다.

## 3. Before: 수업 코드가 실패하는 이유

수업에서 작성한 코드는 다음과 같다.

```sql
-- 에러 케이스: 컬럼 개수가 다르다
select
    `email`,
    `status`
from
    users
where
    status = 'active'
union
select
    `name`,
    `email`,
    `status`
from
    users
where
    status = 'suspended';
```

| 구분 | 조회 컬럼 | 개수 |
|------|-----------|------|
| 첫 번째 `select` | `email`, `status` | 2개 |
| 두 번째 `select` | `name`, `email`, `status` | 3개 |

첫 번째 쿼리는 이름(`name`)을 빠뜨려서 2컬럼이 되었다. 요구사항은 이름, 이메일, 상태를 조회하는 것이므로 첫 번째 쿼리가 틀린 쪽이다.  
컬럼 개수가 다르면 결과를 한 표로 합칠 수 없어서, 이 쿼리는 그대로 실행하면 컬럼 개수 불일치 에러가 난다. 정확한 에러 메시지 원문은 실행해서 확인하지 않았으므로 `확인 필요`로 남긴다.

헷갈리기 쉬운 점은 두 쿼리 모두 `email`과 `status`를 갖고 있어서 얼핏 맞는 것처럼 보인다는 것이다. 개수만 맞추면 된다고 생각할 수 있지만, 규칙에는 순서와 타입 호환도 있다. 그래서 컬럼 목록은 두 쿼리에서 **똑같이** 복사해 쓰는 편이 안전하다.

## 4. After: 컬럼을 name, email, status로 통일한다

첫 번째 `select`에 `name`을 추가해서 두 쿼리의 컬럼을 같은 순서의 3개로 맞춘다.

```sql
select
    `name`,
    `email`,
    `status`
from
    users
where
    status = 'active'
union
select
    `name`,
    `email`,
    `status`
from
    users
where
    status = 'suspended';
```

| 위치 | 첫 번째 `select` | 두 번째 `select` |
|------|------------------|------------------|
| 1번째 | `name` | `name` |
| 2번째 | `email` | `email` |
| 3번째 | `status` | `status` |

이제 두 쿼리의 컬럼 개수, 순서, 타입이 모두 같다. `deleted` 사용자는 어느 `where`에도 걸리지 않으므로 결과에 포함되지 않는다.

## 5. 보충: UNION ALL과 where status in 대안

이 절은 수업 자료에 없던 내용을 MySQL 공식 문서를 근거로 덧붙인 것이다.

**UNION과 UNION ALL.** MySQL 공식 문서에 따르면 `UNION`은 기본적으로 중복 행을 제거하고(`DISTINCT`), `UNION ALL`을 쓰면 중복을 제거하지 않고 모든 행을 그대로 반환한다.

| 구분 | 중복 행 | 사용 상황 |
|------|---------|-----------|
| `union` | 제거한다 | 같은 행이 두 번 나오면 안 될 때 |
| `union all` | 그대로 남긴다 | 중복이 있어도 되거나, 중복이 없다고 알고 있을 때 |

**더 단순한 대안.** 이번 시나리오는 한 테이블에서 `status`만 다른 행을 고르는 것이라서 `UNION` 없이도 된다.

```sql
select
    `name`,
    `email`,
    `status`
from
    users
where
    status in ('active', 'suspended');
```

`UNION`은 서로 다른 테이블이나 서로 다른 조건의 결과를 합칠 때 더 알맞다. 같은 테이블에서 한 컬럼의 값만 나눠 고르는 경우에는 `in`이 읽기 쉽다.

## 정리

- `UNION`은 여러 `select` 결과를 합치는 합집합이며 중복 행은 제거한다.
- 합칠 `select`는 컬럼 개수가 같아야 하고, 같은 위치의 컬럼은 순서와 데이터 타입이 호환되어야 한다.
- 수업 코드의 첫 `select`는 `name`이 빠져 2컬럼이었고, `name`, `email`, `status`로 통일해서 해결했다.

## 더 학습하면 좋은 개념

- **UNION ALL** — 중복 제거 없이 결과를 합친다. `UNION`은 중복 제거 과정이 들어가므로, 중복이 없다고 확신하는 경우에 둘의 차이를 알아두면 쿼리 의도를 더 정확히 표현할 수 있다.
- **IN 연산자** — 한 컬럼에서 여러 값 중 하나와 일치하는 행을 고른다. 같은 테이블에서 조건만 다른 경우 `UNION`보다 간단해지는 지점을 판단할 수 있다.
- **집합 연산 (INTERSECT, EXCEPT)** — 교집합과 차집합을 구하는 연산이다. 합집합인 `UNION`을 이해했다면 같은 집합 개념으로 SQL 결과를 다루는 폭이 넓어진다. MySQL 버전별 지원 여부는 `확인 필요`.
- **JOIN과 UNION의 차이** — `JOIN`은 행을 옆으로(컬럼 방향) 붙이고 `UNION`은 아래로(행 방향) 붙인다. 두 방식을 구분해야 상황에 맞는 쿼리를 고를 수 있다.
