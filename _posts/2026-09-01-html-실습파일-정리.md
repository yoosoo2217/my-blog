# HTML 실습 파일 정리

부트캠프에서 HTML 태그를 배우면서 실습 파일 하나에 26개의 미니 과제를 이어서 풀었다. 번호 순서 그대로 옮기면 "무슨 태그를 왜 쓰는지"보다 "코드가 어떻게 생겼는지"만 남아서, 이번엔 같은 개념을 연습한 것끼리 묶어서 정리했다. 각 묶음마다 대표 코드 하나만 남기고, 그 태그를 왜 쓰는지 · 무엇이 헷갈렸는지를 먼저 적는다.

실습 순서는 문서 뼈대(제목·문단·목록) → 의미 있는 강조 → 표 구조 → div/span → 링크·이미지·미디어 → 종합 실습 순으로 짜여 있었다. 이 흐름대로 정리한다.

## 1. 문서의 뼈대: 제목과 문단 (실습 1, 2)

`h1`~`h3`로 제목의 위계를 나누고 `p`로 문단을 나누는 연습이었다. `h1`은 페이지에서 가장 중요한 제목 하나, `h2`·`h3`는 그 아래 하위 항목이다. 스크린리더나 검색엔진이 이 위계로 문서 구조를 파악하므로, 글자 크기가 아니라 의미 순서로 골라야 한다는 걸 배웠다.

```html
<h1>박유수</h1>
<h2>프론트엔드를 배우는 중</h2>
<h3>좋아하는 것</h3>
<p>안녕하세요. 키즈카페에서 일하다가 개발을 시작했습니다.</p>
<p>지금은 부트캠프에서 HTML을 배우고 있습니다.</p>
```

## 2. 목록: 순서가 의미를 가지는가 (실습 3, 4)

`ul`(순서 없는 목록)과 `ol`(순서 있는 목록)의 차이는 겉모습(점 vs 숫자)이 아니라 **순서에 의미가 있는지**로 갈렸다. "좋아하는 것"처럼 나열 순서가 중요하지 않으면 `ul`, "배우고 싶은 순서"처럼 순서 자체가 정보면 `ol`을 쓴다.

```html
<ul>
    <li>산책 하기</li>
    <li>노래 듣기</li>
</ul>

<ol>
    <li>HTML</li>
    <li>CSS</li>
    <li>JavaScript</li>
</ol>
```

## 3. 의미 있는 강조 vs 순수 스타일 (실습 7)

`s`(취소선), `b`(굵게), `i`(기울임), `sup`(위 첨자)로 상품 소개 문구를 꾸며보는 연습이었다. 여기서 `b`/`i`는 의미 없이 모양만 바꾸는 태그, `strong`/`em`은 "중요하다/강조한다"는 의미를 담는 태그라는 차이를 체감했다. 시각적 구분만 필요하면 `b`/`i`로 충분하지만, 스크린리더에게도 중요함을 전달하려면 `strong`/`em`을 써야 한다.

```html
<h1>겨울 패딩 점퍼</h1>
<p>정가 <s>129,000</s> -> <b>89,000</b></p>
<p>보관 시 1m<sup>2</sup> 이상 공간을 두세요.</p>
```

## 4. 링크와 페이지 이동 (실습 5, 12, 19)

`a href`로 외부 링크를 걸고, `li` 안에 `a`를 넣어 클릭 가능한 목록을 만드는 연습이었다. `li` 안에 `a`를 넣는 12번 실습을 하면서 **"목록"과 "이동 가능한 항목"은 서로 다른 레이어**라는 게 명확해졌다. 목록 구조는 `ul`/`li`가, 클릭 가능하게 만드는 역할은 `a`가 맡아서 두 태그를 겹쳐 쓴다.

```html
<ul>
    <li><a href="https://www.google.com">구글 검색</a></li>
    <li><a href="https://github.com">깃허브</a></li>
</ul>
```

## 5. 이미지와 대체 텍스트 (실습 6, 13, 25)

처음엔 `alt`에 그냥 "사진"이라고만 적었는데, 25번 실습에서 "alt를 제대로 쓰기"를 따로 연습하면서 `alt`가 장식이 아니라 **이미지가 안 보일 때(로딩 실패, 스크린리더) 대신 읽히는 진짜 내용물**이라는 걸 알게 됐다. 그래서 "꽃1"처럼 뭘 찍었는지 알 수 있는 문구로 바꿔 써야 한다.

```html
<img src="sample/image/flower1.PNG" alt="꽃1">
<li>꽃<img src="sample/image/flower4.PNG" alt="꽃"></li>
```

## 6. 미디어 삽입 (실습 10, 17)

`video`/`audio` 태그에 `controls`를 붙이면 재생/정지 UI가 자동으로 생긴다는 걸 배웠고, 17번 실습에서는 `loop` 속성을 추가로 붙여 반복 재생을 시켜봤다. 별도의 재생 버튼 UI를 직접 만들지 않아도 브라우저가 기본 컨트롤을 제공한다는 점이 인상 깊었다.

```html
<video src="sample/video/video1.mp4" controls="controls" loop="loop"></video>
<audio src="sample/audio/major.mp3" controls="controls"></audio>
```

## 7. div와 span: 블록과 인라인의 차이 (실습 9)

같은 목록을 `div`로 묶은 버전과 `span`으로 묶은 버전을 나란히 만들어보니 차이가 눈으로 바로 보였다. `div`는 한 덩어리(블록)라서 각 항목이 줄바꿈되며 세로로 쌓이고, `span`은 인라인이라서 옆으로 이어진다. "어떤 태그를 쓸지"보다 "이 내용이 한 줄을 다 차지해야 하는지, 문장 속 일부인지"를 먼저 판단해야 한다는 걸 배웠다.

```html
<div>커피 내리기</div>
<div>영화 보기</div>

<span>커피 내리기</span>
<span>영화 보기</span>
```

## 8. 표의 구조와 병합 규칙 (실습 8, 15, 16, 20, 21, 22, 23, 26)

표 관련 실습이 26개 중 8개로 가장 많았다. `table`(표 전체), `tr`(행), `th`(제목 셀), `td`(데이터 셀)라는 기본 구조를 먼저 익힌 뒤, `colspan`(가로 병합)과 `rowspan`(세로 병합)을 여러 형태로 반복 연습했다. `th`/`td`는 겉보기엔 볼드체·정렬 차이 정도지만, 실제로는 "제목인가 데이터인가"라는 의미 차이라 스크린리더가 `th`를 기준으로 행/열 이름을 안내한다 — `strong`/`b`와 같은 맥락이다.

실습별로 어떤 태그·속성을 연습했는지 정리하면 다음과 같다.

| 실습 번호 | 실습 주제 | 연습한 태그/속성 | 핵심 개념 |
|---|---|---|---|
| 8 | 배송비 안내 | `table`, `tr`, `th`, `td`, `border` | 표의 기본 뼈대 |
| 15 | 배송 안내 | `colspan` | 셀을 가로로 합치기 |
| 16 | 주간 시간표 | `rowspan` | 셀을 세로로 합치기 |
| 20 | 1주차 평가표 | `rowspan` + `colspan` | 헤더와 데이터 영역에서 함께 병합 |
| 21 | 상품 비교표 | `table` 셀 안에 `img`, `ul`, `a` | 표 셀 안에 다른 태그를 중첩 |
| 22 | 지점별 운영 시간 | `colspan` + `rowspan` 동시 적용 | 한 셀에 두 속성을 함께 주기 |
| 23 | 배송 방법별 요금 | `rowspan` | 반복되는 값을 병합해 줄 수를 줄이기 |
| 26 | 주문내역 | `table`, `tr`, `td` | 기본 구조 재복습 |

```html
<table border="2">
    <tr>
        <th rowspan="2">이름</th>
        <th colspan="2">1주차 점수</th>
        <th rowspan="2">비고</th>
    </tr>
    <tr>
        <td>과제</td>
        <td>출석</td>
    </tr>
</table>
```

`colspan`(col=열을 합친다 → 가로 병합)과 `rowspan`(row=행을 합친다 → 세로 병합)은 단어 뜻으로 외우니 헷갈리지 않았다. 21번 실습의 원본 코드에는 `<td>울 코트/td>`처럼 여는 꺾쇠(`<`)가 빠진 오타가 있었는데, 태그 하나가 안 닫히면 뒤따르는 셀 전체 레이아웃이 밀려서 표가 깨진다는 걸 직접 겪었다. 아래는 오타를 바로잡은 버전이다.

```html
<td>울 코트</td>
```

## 9. 종합 실습: 여러 태그를 한 화면으로 (실습 11, 14, 17, 18, 19, 24)

지금까지 배운 태그를 한 화면에 조합해보는 실습들이었다. 화면 그대로 재현하기(11번), 망가뜨린 코드 되돌리기(14번), 상품 소개 페이지 만들기(18번), 엉망인 들여쓰기 정리하기(24번) 등. 개별 태그를 아는 것과, 여러 태그가 섞인 코드에서 각 태그가 왜 쓰였는지 읽어내는 건 다른 능력이라는 걸 느꼈다. 특히 14번·24번처럼 "있는 코드를 고치는" 쪽이 새로 짜는 것보다 태그 하나하나를 더 신경 쓰게 만들었다.

```html
<h1>핸드드립 커피 세트</h1>
<img src="sample/image/city1.PNG" alt="커피">
<p>원두를 갈아 직접 내려 마시는 도구를 한 상자에 담았습니다.</p>
<h4>구성품</h4>
<ul>
    <li>드리퍼</li>
    <li>종이 필터 100장</li>
</ul>
<ol>
    <li>물을 90도까지 끓입니다.</li>
    <li>필터를 드리퍼에 올립니다.</li>
</ol>
```

## 막혔던 것

- 처음엔 `alt`에 아무 문구나 채우면 되는 줄 알았는데, 25번 실습을 하면서 "이미지가 안 보일 때 대신 읽히는 내용"이라는 걸 알고 나서야 왜 의미 있는 문구가 필요한지 이해했다.
- `colspan`/`rowspan`이 가로/세로 중 어느 쪽인지 계속 헷갈렸는데, col(열)=가로, row(행)=세로라는 단어 뜻으로 정리하고서야 안 헷갈리게 됐다.
- 21번 실습에서 `<td>울 코트/td>`처럼 여는 꺾쇠가 빠진 오타를 보고, 태그는 열고 닫는 짝이 정확히 맞아야 표 레이아웃이 안 깨진다는 걸 몸으로 배웠다.
- `b`/`i`와 `strong`/`em`처럼 겉보기엔 똑같아 보이는 태그도 "의미"와 "스타일"로 나뉜다는 걸 7번 실습을 하면서 처음 알았다.

## 오늘 정리

- 26개의 개별 실습을 문서 뼈대 → 의미 있는 강조 → 표 구조 → 레이아웃 조각(div/span) → 링크·이미지·미디어 → 종합 실습 순으로 묶어보니, 각 태그가 "왜 그 형태로 존재하는지"가 더 뚜렷하게 보였다.
- 특히 표 관련 실습이 절반 가까이 됐는데, `th`/`td`의 의미 차이와 `colspan`/`rowspan`의 방향을 헷갈리지 않고 쓰는 게 이번 실습의 핵심이었다.

## 더 학습하면 좋은 개념

- **웹 접근성(a11y)과 스크린리더** — `alt`, `strong`/`em`, `th` 모두 결국 "스크린리더가 이 태그를 어떻게 읽어주는가"와 연결된 개념이다. 실제 스크린리더로 표나 목록을 들어보면 의미 태그의 중요성이 더 체감될 것 같다.
- **시맨틱 태그 (header, nav, main, article, section, footer)** — `div`로 나눈 영역에 의미를 부여하는 다음 단계로, 검색엔진과 보조기기가 페이지 구조를 이해하는 데 도움을 준다.
- **CSS 박스 모델** — 오늘 배운 `div`/`span`, `table` 셀들을 실제로 배치하고 꾸미려면 margin/padding/border 개념이 필요하다.
- **표(table)의 접근성 속성 (scope, caption)** — `th`에 `scope="col"`/`scope="row"`를 붙이면 스크린리더가 어떤 열/행의 제목인지 더 정확히 안내한다는 걸 다음에 찾아보고 싶다.
