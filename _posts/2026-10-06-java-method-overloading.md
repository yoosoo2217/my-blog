같은 이름의 메소드를 여러 개 만들 수 있는 경우도 있고, 컴파일 에러가 나는 경우도 있다.  
[이전 글]({{ site.baseurl }}/java-methods.html)에서는 "오버로딩(Overloading)"이라는 단어만 짚고 넘어갔는데, `OverloadingTest` 클래스를 직접 만들어서 어떤 변화가 오버로딩으로 인정되는지 하나씩 확인했다.

> **TL;DR**
> - 오버로딩은 "같은 이름, 다른 메소드 시그니처"일 때 성립한다.
> - 시그니처는 메소드명과 매개변수(타입·개수·순서)로 결정된다.
> - 접근 제한자·반환 타입·매개변수 이름만 바꾸면 중복 정의로 컴파일 에러가 난다.

## 1. 오버로딩의 기준은 메소드 시그니처다

**메소드 시그니처**는 메소드를 서로 구분하는 고유한 값으로, `메소드명([매개변수])` 부분, 즉 메소드 이름과 매개변수 구성(타입·개수·순서)으로 결정된다. 접근 제한자나 반환 타입, 매개변수 이름은 시그니처에 포함되지 않는다.

**메소드 오버로딩**은 이 시그니처가 다르면, 같은 이름의 메소드를 여러 개 만들 수 있는 문법이다. 매개변수 구성만 다를 뿐 같은 동작을 하는 메소드들을 하나의 이름으로 묶어 쓸 수 있어서, 호출하는 쪽에서는 "입력이 다르면 알아서 맞는 메소드가 실행된다"고 생각하고 코드를 짤 수 있다.

## 2. OverloadingTest 코드

```java
package com.wanted.oop.b_oop.e_overloading;

public class OverloadingTest {

    /*comment. 메소드의 오버로딩
        메소드 시그니처란?
        - 메소드를 식별할 수 있는 고유한 값
          메소드명([매개변수])
          이 부분이 메소드의 시그니처라고 불리운다.
        - 매소드 시그니처에 따라서 같은 이름을 가진 것에 대해 여러가지 메소드를 만들 수 잇다.
       */

    // 오버로딩을 이용한 테스트 기준 메서드
    public void test() {
    }

    // 메소드의 시그니처가 동일하면 Error 발생
    // public void test() {}

    // 접근제한자를 변경해도 시그니처가 동일 -> Error 발생
    // private void test() {}

    // 반환 타입을 변경해도 시그니처가 동일하여 Error 발생
    // private int test() {
    //     return 0;
    //}

    // 매개변수 유무에 다른 오버로딩 성립
    public void test(int num) {}

    // 매개 변수 명은 메소드 시그니처에 영향을 주지 않는다
    // public void test2(int num) {}

    // 매개변수 개수는 메소드 시그니처에 영향을 미친다
    public void test(int num, String str) {}


    //매개변수 순서에 따른 오버로딩 성립
    public void test(String str, int num) {}

    // 메소드 이름은 시그니처이기 때문에 Error 소멸
    public void test2() {

    }
}
```

기준이 되는 `test()`를 하나 두고, 거기서 접근 제한자·반환 타입·매개변수 개수·매개변수 순서·메소드 이름을 하나씩 바꿔보면서 어떤 변화가 오버로딩으로 인정되는지, 어떤 변화가 그냥 중복 정의로 에러가 나는지 주석으로 직접 남겨뒀다.

## 3. 개수·타입·순서만 오버로딩을 만든다

코드에 남긴 주석들을 표로 정리하면 다음과 같다.

| 바뀐 요소 | 오버로딩 성립 여부 | 코드 예시 |
|---|---|---|
| 매개변수 개수 | 성립 | `test()` vs `test(int num)` |
| 매개변수 타입·순서 | 성립 | `test(int num, String str)` vs `test(String str, int num)` |
| 접근 제한자만 다름 | 불성립 (Error) | `public void test()` vs `private void test()` |
| 반환 타입만 다름 | 불성립 (Error) | `public void test()` vs `private int test()` |
| 매개변수 이름만 다름 | 불성립 (Error) | `test(int num)` vs `test(int number)` (시그니처가 동일하게 취급됨) |
| 메소드 이름 자체가 다름 | 오버로딩 관계 아님 (별개 메소드) | `test()` vs `test2()` |

표에서 확인할 수 있듯, 매개변수의 **개수·타입·순서**는 시그니처를 바꾸기 때문에 오버로딩이 성립하지만, 접근 제한자·반환 타입·매개변수 이름은 시그니처에 포함되지 않아서 이 셋만 바꾸면 자바 컴파일러 입장에서는 "같은 메소드를 두 번 정의한 것"으로 보고 에러를 낸다.  
반대로 `test2()`처럼 이름 자체가 다르면, 매개변수가 같든 다르든 애초에 오버로딩 관계가 아니라 그냥 서로 다른 메소드다.

## 4. 정리

- 메소드 시그니처는 `메소드명 + 매개변수(타입·개수·순서)`로만 결정된다. 접근 제한자·반환 타입·매개변수 이름은 시그니처에 영향을 주지 않는다.
- 오버로딩은 "같은 이름, 다른 시그니처"일 때만 성립한다. 시그니처가 같으면 중복 정의로 컴파일 에러가 난다.
- 이름 자체가 다르면 오버로딩이 아니라 별개의 메소드다.

다음에 볼 것은 아래 "더 학습하면 좋은 개념"에 적었다.

## 더 학습하면 좋은 개념

- **오버라이딩(Overriding)** — 이름이 비슷해서 자주 헷갈리는 개념인데, 오버로딩은 한 클래스 안에서 매개변수를 다르게 하는 것이고 오버라이딩은 상속 관계에서 부모 메소드를 자식이 재정의하는 것이다. 둘의 차이를 정리하면 메소드 관련 개념이 한 번에 정리될 것 같다.
- **가변 인자(Varargs, `...`)** — 매개변수 개수가 정해지지 않은 경우, 오버로딩으로 모든 경우의 수를 다 만드는 대신 가변 인자를 쓸 수 있다는 걸 알게 돼서, 오버로딩과 언제 구분해서 써야 하는지 궁금해졌다.
- **오버로딩 메소드 선택 규칙(Overload Resolution)** — 매개변수 타입이 `int`/`long`/`double`처럼 자동 형변환이 가능한 경우, 여러 오버로딩 메소드 중 컴파일러가 정확히 어떤 걸 선택하는지는 오늘 다루지 않았는데, 다음에 직접 호출해보면서 확인해보고 싶다.
