"SQL 기초 강의 수강생들의 평균 점수보다 높은 점수를 받은 학생은 누구인가?" 같은 문제는 `WHERE` 한 줄로 풀리지 않는다.  
비교할 값인 평균 점수를 먼저 구해야 하는데, 그 값을 구하는 것도 쿼리이기 때문이다.  
이렇게 조건이 충분하지 않을 때 쿼리 안에 또 다른 쿼리를 넣는 것이 서브쿼리(Subquery)다.

> **TL;DR**
> - 서브쿼리는 2개 이상의 쿼리문을 조합해서 1개의 쿼리문으로 만드는 것이다.
> - `WHERE`절 서브쿼리는 조건에 쓸 값을 대신 구해 주고, `FROM`절 서브쿼리는 `SELECT` 결과를 가상 테이블처럼 쓴다.
> - `FROM`절 서브쿼리에는 반드시 별칭(`as`)을 붙인다.

환경: MySQL (버전 `확인 필요`), 데이터베이스 `wanted_lms`. 실습 테이블은 `users`와 `courses`이고, 각 쿼리의 결과는 이 글에 옮기지 않았다.

## 1. 왜 쿼리 안에 쿼리가 필요할까

실습에서 다룬 문제는 두 가지다. 두 문제 모두 답을 바로 구할 수 없고, 먼저 알아야 하는 값이 하나 있다.

| 문제 | 1단계 | 2단계 |
|------|-------|-------|
| SQL 기초 강의 수강생들의 평균 점수보다 높은 점수를 받은 학생의 이름은? | SQL 기초 강의 수강생들의 평균 점수 구하기 | 평균 점수보다 높은 점수를 받은 학생 조회 |
| '홍길동' 사용자와 같은 년도에 가입한 모든 사용자의 이름과 가입일은? | '홍길동'의 가입 년도 파악하기 | 그 년도에 가입한 사용자의 이름과 가입일 조회 |

사고 순서는 같다. 비교 기준이 되는 값을 먼저 구하고, 그 값으로 행을 거른다. 평균 점수 문제는 재료로 받은 실습 코드에 쿼리가 없어서 이 글에서는 사고 순서만 적는다. 이어서 쿼리가 있는 두 번째 문제로 단계별로 풀어 본다.

## 2. 단계별로 풀기: 홍길동과 같은 해에 가입한 사용자

### 1단계: 홍길동의 가입 년도를 구한다

```sql
select
    year(created_at)
from
    users
where
    name = '홍길동';
```

`year()`는 날짜에서 년도만 꺼내는 함수다. 이 쿼리의 결과가 바로 2단계에서 필요한 값이다.

### 2단계: 그 년도에 가입한 사용자를 조회한다

2단계의 쿼리를 `where` 없이 쓰면 전체 사용자가 나온다.

```sql
select
    name,
    created_at
from
    users;
```

여기에 `year(created_at) = (년도)` 조건을 붙이고 싶은데, 그 년도가 1단계의 결과라는 점이 문제다. 1단계를 따로 실행해서 나온 값을 눈으로 보고 직접 입력하면 풀리기는 한다. 하지만 쿼리가 2번 필요하고, 사람이 중간에 끼어야 한다. 서브쿼리는 이 중간 과정을 쿼리 하나로 합친다.

### 합치기: WHERE절에 서브쿼리를 넣는다

```sql
select
    name,
    created_at
from
    users
where
    year(created_at) = (
        select
            year(created_at)
        from
            users
        where
            name = '홍길동'
    );
```

괄호 안의 안쪽 쿼리(서브쿼리)가 1단계, 바깥쪽 쿼리가 2단계다. 안쪽 쿼리가 반환한 값이 `=` 오른쪽 자리에 들어간다.

한 가지 주의할 점이 있다. 이 쿼리는 `=`로 비교하므로, 서브쿼리가 값을 하나만 돌려준다는 전제가 있다. 이름이 '홍길동'인 사용자가 여러 명이면 어떻게 되는지는 실습 재료에 없어서 이 글에서는 다루지 않는다. `확인 필요`로 남겨 둔다.

## 3. FROM절 서브쿼리: 결과를 가상 테이블로 쓴다

`SELECT`의 결과를 마치 하나의 테이블처럼 쓰는 것을 `FROM`절 서브쿼리라고 하고, 이 결과는 가상 테이블이라고 부른다. 교육자별 개설 과정 수를 구해 `users`와 합치는 예제다.

```sql
select
    u.name as '교육자 이름',
    aut.course_count as '교육자 개설 과정 수'
from
    users u
    join
    (
        select
            author_id,
            count(*) as course_count
        from
            courses
        group by
            author_id
    ) as aut
    on u.user_id = aut.author_id
order by `교육자 개설 과정 수` desc;
```

동작 순서는 다음과 같다.

1. 괄호 안의 쿼리가 `courses`를 `author_id`별로 묶어 `author_id`와 `course_count`(과정 수) 두 열을 만든다.
2. 이 결과에 `aut`라는 별칭을 붙여 가상 테이블로 취급한다.
3. `users`와 `aut`를 `u.user_id = aut.author_id` 조건으로 `join`한다.
4. 마지막으로 `교육자 개설 과정 수`가 큰 순서로 정렬한다.

`courses` 테이블에는 이름 열이 없고 `author_id`만 있다. 그래서 이름은 `users`에서 가져와야 하고, 집계(`count`)와 합치기(`join`)를 한 쿼리에서 하려고 `FROM`절 서브쿼리를 썼다. 서브쿼리 결과에 붙인 `as aut`는 선택이 아니라 필수다. 가상 테이블에도 이름이 있어야 바깥 쿼리에서 `aut.course_count`처럼 가리킬 수 있기 때문이다.

## 4. WHERE절 서브쿼리와 FROM절 서브쿼리 비교

| 비교 기준 | `WHERE`절 서브쿼리 | `FROM`절 서브쿼리 |
|-----------|---------------------|---------------------|
| 위치 | `where` 조건의 비교값 자리 | `from` 또는 `join` 뒤 |
| 안쪽 쿼리의 역할 | 조건에 쓸 값을 구한다 | 결과를 가상 테이블로 만든다 |
| 이 글의 예제 | 홍길동의 가입 년도 | 교육자별 개설 과정 수 |
| 별칭 | 필요 없다 | 필수다 (`as aut`) |
| 이럴 때 쓴다 | 조건을 모르는 값으로 걸러야 할 때 | 집계한 결과를 다른 테이블과 합쳐야 할 때 |

## 정리

- 서브쿼리는 조건이 충분하지 않을 때 쿼리를 2개 이상 조합해 1개로 만드는 방법이다. 먼저 구할 값(1단계)과 그 값으로 거르는 조건(2단계)으로 문제를 나누면 어디에 서브쿼리를 넣을지 보인다.
- 조건에 쓸 값이 필요하면 `WHERE`절에, 집계한 결과를 테이블처럼 써야 하면 `FROM`절에 넣는다.
- `FROM`절 서브쿼리에는 별칭이 필수다.
- 다음에 볼 것은 서브쿼리가 여러 값을 돌려줄 때의 비교 방법이다.

## 더 학습하면 좋은 개념

- **다중 행 서브쿼리 (`IN`, `ANY`, `ALL`)** — 서브쿼리가 여러 값을 돌려줄 때 `=` 대신 쓰는 연산자다. 이 글의 `WHERE`절 예제는 값이 하나라는 전제가 있어서, 그 전제가 깨졌을 때를 알아야 한다.
- **상관 서브쿼리(Correlated Subquery)** — 안쪽 쿼리가 바깥 쿼리의 값을 참조하는 서브쿼리다. 행마다 다른 기준으로 비교해야 할 때 필요하다.
- **JOIN과 서브쿼리의 선택** — 같은 결과를 두 방식으로 쓸 수 있는 경우가 많다. 어느 쪽이 읽기 쉬운지, 실행 계획은 어떻게 다른지 비교해 두면 쿼리를 고르는 기준이 생긴다.
- **파생 테이블(Derived Table)** — 공식 문서에서 `FROM`절 서브쿼리를 부르는 이름이다. 용어를 알아 두면 공식 문서를 검색할 때 도움이 된다.
- **CTE (`WITH` 절)** — 서브쿼리에 이름을 붙여 쿼리 위쪽에 따로 적는 문법이다. 서브쿼리가 중첩되어 읽기 어려워질 때 쓸 수 있다. (사용 가능한 MySQL 버전은 `확인 필요`)
